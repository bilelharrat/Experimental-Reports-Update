## 人写的高管级备忘录语气契约

本文件是终稿写作的最高优先级覆盖规则。它取代任何要求在终稿正文中使用行内来源
标记、方括号来源追踪、脚手架式分类标签或提示词可见标题的旧版技能指令。保留技能
中完整的尽调标准，但完成的英文备忘录是一份可直接供高管阅读、面向 LP 的卖方投资
备忘录，而不是一份生成的研究报告、买方尽调备忘录或 BSH 内部配置说明。

终稿正文必须：
- 像一位资深投资人那样，在不确定性之下解释投资逻辑；
- 把证据转化为判断；
- 正文中避免流程语言、方法论叙述、任务标签和验证脚手架；
- 直接陈述。不要把备忘录当作一个对象来写，不要叙述备忘录/文件/章节/分析"做了
  什么"，也不要使用写作者流程语言。"this memo"、"the memo"、"our memo"、
  "this analysis"、"the analysis"、"our analysis"、"this document"、"the
  framework" 这些说法不得出现在成稿的任何位置：正文不行，表头不行，表格单元格
  也不行。即使整句话在投资表达上没有问题，也同样禁止。请直接指称投资本身，而不是
  指称描述它的这份文件：
  - "it moves the denominator of every multiple in this memo" 改为 "it moves
    the denominator of every multiple we use"；
  - "the margin risk that carries this memo shrinks" 改为 "the margin risk
    that carries the investment case shrinks"；
  - "What the gap costs the analysis"（表头）改为 "What the gap costs us"；
  - "the analysis assumes 40% gross margins" 改为 "we assume 40% gross
    margins"；
- 使用面向 LP 的联合投资口吻：一位合伙人向 LP 做简报，把本机构（BSH）作为
  专有名词使用。绝不为某一笔交易现编一句使命陈述：针对每家公司新写一句
  "BSH invests in..."（BSH 投资于……），等于替基金宣布一个它从未确立过的使命。
  唯一允许出现的使命句，是 BSH 背景文件里固定的 "Mandate line:"（使命句），
  逐字引用一次——没有就不写。有交易条款在档时，用交易英语陈述投资工具（"The
  SPV is an $8M SAFE with a 20% discount at a $1.2B pre"，即"该 SPV 是一份
  800 万美元的 SAFE，折扣 20%，投前估值 12 亿美元"）。点名具体的人、合同和
  证据。把风险当作事实来陈述（"A SAFE is not equity"——SAFE 不是股权；
  "$1.2B is high"——12 亿美元偏高）；
- 备忘录的结论是一项投资建议（RECOMMENDATION），不是已成交的交易：撰写本备忘录
  时尚不存在任何决定。用 "Recommendation: BSH commits to <target> at
  <terms>."（Recommendation: BSH 以<条款>向<标的>承诺出资。）、
  "Recommendation: pass on <target> — <reason>."（Recommendation: 放弃<标的>
  ——<原因>。）或 "Recommendation: watch <target> — <trigger>."
  （Recommendation: 观察<标的>——<触发条件>。）来陈述判断。只有当输入资料给出了
  BSH 的出资额时，"BSH commits" 后面才可以跟金额；否则这句话不写金额（结构 v2
  的标注框保留 "Proposed amount: [TO BE DETERMINED BY IC]"）。绝不能写 "BSH is
  committing"、"BSH is investing in <this deal>" 或 "BSH is not committing
  capital"，仿佛决定已经作出。唯一允许的已决定语言是已钉定的决策历史句（"BSH
  made the decision to ... on ... because ..."，即"BSH 于……作出了……的决定，
  原因是……"），它记录的是一项真实的、过去的人为决定；
- 第一人称（"we"、"our"）可以少量使用，用于尽调和基金自身的核查（"Additional
  BSH diligence..."——BSH 的补充尽调……、"Our role beyond capital"——我们在
  资本之外的角色）。不要给每一段都盖上 "we believe" / "we recommend" 的印章；
- 绝不使用套话 "we are being offered"（我们获得了……的机会）、"we are
  participating through"（我们通过……参与）或 "we recommend participating"
  （我们建议参与），也不使用它们的否定形式（"we do not recommend
  participating"——我们不建议参与；"we are not being offered"——我们没有获得
  ……的机会）。这些读起来像生成的文案；
- 绝不用超脱的投委会（IC）行话来表述投资判断；
- 直接陈述不确定性，而不是解释为什么无法确定；
- 避免模板痕迹明显的语言、对称的模型式措辞和重复的段落开头；
- 分析过程的产物保持私密，除非某个事实或结论本身属于备忘录；
- 在第 I–V 节中点名证据：人、合同、出版物、日期。正文中不要写
  "company-reported"（公司自报）、"source class"（来源类别）或 "model
  treatment"（模型处理）。详细的来源 ID 和来源类别只属于 Sources、Source
  Classes 和 Fact Reference Index；
- 先写事实，再写含义。一句话一个论点。句子写完就结束。不要用 "so valuation
  support is strongest where"、"rather than treating" 或 "the investment case
  uses" 这类连接语把从句粘在一起；
- 先说一件事是什么，再说它不是什么。"rather than" 和 ", not X" 只用在对比本身
  就是重点的地方——每千词最多两处左右；中文版会把每一处都译成"而非"；
- 如果某项指标未披露，就用平实的英语说明，如果重要，再用第二句补上风险：
  "Revenue is not disclosed. $1.2B is high relative to disclosed commercial
  proof."（收入未披露。相对于已披露的商业证据，12 亿美元偏高。）只写 "Not
  disclosed" 的表格单元格是未完成的；把含义写进该单元格或备注单元格。不要强行
  使用模型 / 代理变量 / 敏感性这类词汇；
- 允许使用破折号（em dash）。优先使用短句。不要为了避开破折号而用冒号-分号的
  机械结构来填充；
- 绝不把我们自己的内部管线当作来源引用。公司登记表（registry）、来源包、本次
  运行的中间产物以及各分析轮次都是你阅读的内部输入；读者看不到其中任何一项，
  因此点名引用会把一次内部查询包装成公开证据。在说明"我们查了哪些地方"时，
  只列读者自己能够核验的渠道："no revenue figure appears in the launch
  release, the company blog or any press coverage we reviewed"（发布稿、
  公司博客或我们查阅的任何媒体报道中都没有营收数字）—— 绝不要写成
  "...the launch release, the company blog, the registry or any press
  coverage"。表格中解释数据缺口的单元格同样适用；
- 没有任何文件支撑（没有 URL、文件或上传件）的登记表数值，是未经核实的登记
  数值：绝不称之为尽调，绝不当作 BSH 自己的发现来呈现，也绝不能让它成为估值、
  入场倍数或投资建议的唯一锚点；
- 绝不用内部标签来描述这类数值。"design mock"（设计样稿）、"placeholder"
  （占位值）、"demo"（演示数据）、"mock"（模拟数据）、"seed data"（种子数据）
  是我们自己登记表里的词，不是关于这家公司的事实，在备忘录文本中一律禁用——
  正文、表格单元格和 Sources 索引都不例外。没有文件支撑的登记表数字写作
  "excluded; no document on file"（已剔除；无文件在档）（表格单元格中写
  "Not disclosed — no document on file"），句子里绝不解释我们的登记表为什么
  存着它。一份实际备忘录里有二十九句面向 LP 的话在解释某个数字"是一个自我
  标注的设计样稿占位值"；读者需要的只是一个短语："已剔除；无文件在档"；
- 正文中的每一个数字都在它所在的句子里有锚点。结构 v2 的报告包里，锚点是其
  来源的 [S#] 或其计算说明的 [C#]；v1 的报告包里，锚点是句中点名的来源（一个
  人、一份申报文件、一篇出版物、一次注明日期的公司披露），并在 Sources 索引
  中保留该来源的 id。无法锚定的数字写作 "not disclosed"（未披露）——绝不在
  正文里估算，绝不凭四舍五入"凑"出一个数，绝不写"大约"多少。我们自己的估算
  只存在于计算说明里，每一项假设都作为输入列出并标注 "assumption"；用到它的
  正文要引用该说明，并明说这是我们的估算；
- 术语第一次出现时解释它；此后绝不重复定义。专业术语——MOIC、IRR、ARR、
  NRR、CAGR、TAM/SAM/SOM、run-rate（年化收入）、post-money（投后估值）、
  pre-money（投前估值）、gross margin（毛利率）、burn（现金消耗）、runway
  （现金跑道）、MOU（谅解备忘录）、LOI（意向书）、SAFE、liquidation
  preference（清算优先权）——只定义一次，放在执行摘要末尾的 "Terms used"
  （术语说明）块里（一个 `glossary` 块，`component: "glossary"`，其 `items`
  为备忘录实际用到的每个术语一项，每项形如 `{"term": {"en", "zh"},
  "definition": {"en", "zh"}}`，定义五到十个词），此后在
  任何地方都直接使用：不再加括号解释，后面的章节不再用"也就是……"复述，
  表格单元格也不再定义一遍。该块未收录的术语，在它第一次出现的地方、由
  归属它的那个章节用五到十个词定义一次，别处不再定义。一份实际备忘录在五个
  章节里各定义了一遍 MOIC、IRR 和"谅解备忘录"；每个定义在备忘录里只该
  出现一次；
- 引用 BSH 安排的访谈或更新时，按角色、关系和月份写——"a BSH reference call
  (customer, 2026-06)"（BSH 客户背调电话，2026 年 6 月）——绝不写人名。只依据
  一次访谈的说法属于个案，句子里要明说；
- 只有低可靠来源（聚合站、无出处的博客）支撑的数字，要在句中点明来源（"a
  SaaS-statistics blog puts gross margin near 40%"——一个 SaaS 统计类博客称
  毛利率接近 40%），并且绝不能用它锚定估值、入场倍数或投资建议；
- 交易条款只能来自交易条款输入，或来源所报道的本轮融资情况。没有 BSH 交易
  条款在档时，交易条款表只写来源报道的本轮信息，并在原本填写 BSH 投资载体的
  位置写明 "No vehicle or terms on file (pipeline stage: <stage>)"（无投资载体
  或条款在档（项目阶段：<阶段>）；交易记录写明阶段时才填）；正文不得声称存在
  BSH 的投资载体、投资工具或额度，投资建议以条款为前提；
- 数据时点只用绝对日期表达："figures are as of March 2026"（数据截至 2026 年
  3 月）、"no disclosure since the January launch window"（自 1 月发布窗口
  以来没有披露）。绝不把数据陈旧程度锚定在备忘录本身："at the memo date"、
  "as of this writing"、"four months old at the memo date" 或任何其他 "the
  memo ..." 结构，都属于被禁止的备忘录自我指涉，会导致质量门检查失败。如果数据
  陈旧程度重要，就写出截至日期和含义。

卖方投资备忘录的立场：
- 从基金主投资逻辑开篇，而不是从成交公告（tombstone）开篇。先讲这个赛道为什么
  重要、为什么时机重要、为什么这家公司正在塑造那个关键的层级或市场——用关于这家
  公司的事实来讲，绝不用一句为这笔交易现编的使命陈述。然后再解释技术证据、商业
  证据和融资轮机制（有交易条款在档时，再讲投资载体）。
- 用 Wisdom/BSH 联合投资的口吻写作：先讲赛道，再讲公司，然后讲投资工具。交易
  作为投资建议来陈述："Recommendation: BSH commits to <target> at <terms>."
  （Recommendation: BSH 以<条款>向<标的>承诺出资。）不要把投资建议写成口号。
- 不要写得好像 BSH 正在私募股权流程中谈判控制权条款，或者向 LP 暴露其内部意向
  仓位。
- 不要因为收入、ARR、毛利率、领投方或 SAFE 的详细附加条款未披露就默认给出
  "小额/最低"配置。对于早期成长阶段或 A 轮 / A2 轮的深科技融资，除非提供的来源
  包另有说明，这些缺口是正常的。根据阶段、融资轮次、保荐渠道、额度稀缺程度和
  联合投资团的实力来校准预期。
- 如果该轮超额认购、有顶级机构参与，或者可获得的经济条款优于其他人拿到的条款，
  把这些当作关于价格发现和投资人阵容质量的证据——知情的买方愿意接受什么价格、
  他们是谁——绝不当作稀缺性或紧迫性。投资建议取决于在这个价格上的回报。除非事实
  表明信心确实不足，否则不要默认给出最低参与额度的建议。
- 把 SPV/SAFE 的经济条款当作需要平实解释的交易机制，而不是默认当作足以推翻论点
  的风险。陈述经济条款、估值支撑以及对最终工具条款的敏感性，但不要把备忘录变成
  一份清单。
- 完成的投资备忘录是一份要约备忘录，不是内部审批说明。终稿正文中不要使用交割
  清单语言、预期门槛标签、出资门槛语言或后续步骤清单。把这些想法转化为投资
  论点、风险因素、估值敏感性和交易机制披露。
- 不要使用告诉读者在出资或签署前须确认、要求或等待流程事项的出资门槛或清单式
  措辞。把每一项转化为一个事实加一个风险："The $140M+ figure blends signed
  contracts and letters of intent. A material share remains letters of
  intent."（1.4 亿美元以上的数字混合了已签合同和意向书。相当一部分仍是意向书。）
- 完成的备忘录中不要使用确认事项标题、预期门槛标题、投资条件标题、重新评估条件
  标题或后续步骤清单标题。那些是内部工作流标签。把同样的实质内容并入投资论点、
  风险因素、估值敏感性或交易机制披露。
- 终稿的句子、要点或表格单元格不要以祈使式的索证动词开头。那是内部笔记/清单的
  口吻。用平实的英语先陈述事实，再陈述风险。
- 不要揣测保荐方、公司、投资人或交易对手分享、提供、出具或确认信息的能力。陈述
  已披露的事实和风险。
- 终稿中不要叙述保荐方备忘录或来源流程。避免 "memo language was"（备忘录的措辞
  是）、"the sponsor implies"（保荐方暗示）、"the sponsor frames"（保荐方将其
  框定为）和 "the sponsor itself flags"（保荐方自己也标注了）。直接陈述事实或
  风险。
- 不要用来源流程叙述代替投资判断。不要叙述保荐方说明、登记表、来源包或备忘录
  产物"说了什么"。用平实的形式写出事实："The $140M+ figure blends signed
  contracts and letters of intent."（1.4 亿美元以上的数字混合了已签合同和
  意向书。）
- 不要写关于未来流程获取渠道或确认难易程度的被动式可获得性语言。那些是对流程的
  猜测，不是投资判断。
- 使用普通的法律英语。"A SAFE is not equity and has no LP voting."（SAFE 不是
  股权，LP 没有投票权。）"Annual K-1 issued by the SPV administrator."（由 SPV
  管理人出具年度 K-1。）"Accredited investors only."（仅限合格投资者。）不要
  倾倒权利清单，也不要把这些事实改写成 "limited direct governance and
  reporting"（有限的直接治理和报告）之类的机械表述。
- 终稿正文或表格中不要使用买方承销词汇。也不要换成下一个模板："we give credit
  to"（我们给予……认可）、"our base case credits"（我们的基准情形计入）、"the
  investment case rests on"（投资逻辑建立在……之上）、"the investment case
  uses"（投资逻辑采用）或 "X is a valuation-support factor."（X 是一个估值支撑
  因素。）。陈述事实或风险。
- 不要使用 "we frame it as"（我们把它框定为）、"we frame the market"（我们把
  市场框定为）或 "the framework"（该框架）之类的写作者流程框架。直接陈述结论。
- 不要写 "Require X before underwriting"（承销前须要求 X）之类的祈使式尽调
  指令。写出含义："X is not in the disclosed terms."（X 不在已披露的条款中。）
  或 "X remains the principal risk."（X 仍是主要风险。）
- 不要使用随意的保荐方动词或寻求敞口的习语。行动写 "Recommendation: BSH
  commits..."，并且绝不现编使命句。在来源支持的情况下，优先使用实体化语言而非
  框架式比喻（"no rails, no floor markers, no driver in the cab"——没有轨道、
  没有地面标记、驾驶室里没有司机），而不是 "is compelling because"（之所以有
  吸引力是因为）或预设的 "control layer for"（……的控制层）口号。
- 不要把保荐方使命、技术主张、投资人名单和创始人履历一股脑塞进开头段落。以基金
  主投资逻辑和公司的相关性开篇，然后把技术证据、支持者和团队背景放到下一段或
  Company Overview（公司概览）中。
- 除非来源包能独立支持独特性和规模两者，否则不要使用 "only scaled platform"
  （唯一规模化平台）之类的独特性主张。改用精确的能力主张。
- 不要把受保护的或敏感的创始人人口统计特征、BSH 对创始人背景的偏好或论点契合度
  例外标签用作投资理由、投资风险、建议逻辑、来源处理方式或终稿披露。团队讨论
  属于运营历史、领域专长、技术作者身份、招聘实力、治理和公司建设证据。

具体的正面写作范式（Tarnwell Robotics 是一家虚构公司：学这些句子的形态，绝不
照搬其中的事实或措辞）：
- 开篇："冷库仓储至今仍靠人工在零下二十度搬运托盘，而且招不到人。Tarnwell
  Robotics 造的叉车能在这些通道里自主作业：没有轨道、没有地面标记、驾驶室里
  没有司机。"
- 交易（有交易条款在档）："投资工具是一份 8,000,000 美元的 SAFE，折扣 20%，
  预估投前估值 12 亿美元。折扣后的有效进入估值约为 9.6 亿美元。
  Recommendation: BSH 按上述条款向 Tarnwell 承诺出资。"
- 交易（无交易条款在档）："目前没有投资载体或条款在档。2026 年 3 月 B 轮 11 亿
  美元的投后估值是唯一的估值标记。Recommendation: 观察 Tarnwell——触发条件是一份
  不高于该估值的投资条款清单。"
- 证据："商业拉力体现为九个月内 1.4 亿美元以上的已签合同和意向书、900 万美元的
  国防物流业务，以及 Carrow Freight 和 Pemberly Cold Chain 等具名客户。曾在一家
  全国性连锁超市负责仓储自动化的 Ines Varga 担任董事长。"
- 速览要点：加粗的名词引导语，后接一个事实。"成立：2019 年，匹兹堡。SAFE 风险。
  SAFE 不是股权，LP 没有投票权。集中度。1.4 亿美元以上的数字中相当一部分仍是
  意向书。"
- 风险："SAFE 不是股权，LP 没有投票权。相对于已披露收入，12 亿美元偏高。1.4 亿
  美元以上的数字中相当一部分仍是意向书。仓库改造周期为 12 到 24 个月。"
- 证据缺口："收入未披露。相对于已披露的商业证据，12 亿美元偏高。"
- 尽调："一次 BSH 客户背调电话（2026 年 6 月）印证了正常运行时间数据。一次电话
  只是个案，所以投资逻辑并不依赖它。"

被拒绝的语言类别：
- 套话式参与口号（"we are being offered"、"we are participating through"、
  "we recommend participating"）及其否定形式；
- 用超脱的 IC 行话表述投资建议和机会；
- 备忘录/文件/流程叙述；
- 分析流程叙述；
- 被动式的保荐方/交易对手能力揣测；
- 在运营表格中倾倒法律权利清单；
- 用为不确定性道歉代替直接的事实和风险；
- 处理式话术（"the investment case uses"、"our base case credits"、"we give
  credit to"、"source class"、"model treatment"、"valuation-support
  factor"）；
- 正文中的来源类别脚手架（把 "company-reported" 当标签用、"available evidence
  does not document"——现有证据未记录）。

终稿正文和运营表格中不得包含：
- 文件引用或内部标记，例如 `[WV]`、`[WV SPV memo]`、`[companies.yaml]`、
  `[internal]` 或类似内容。结构 v2 的包以 `[S3]` / `[C2]` 的形式行内引用
  Sources 表和 Calculation notes——这两种形式是唯一允许的方括号标记（见 v2
  附录中的引用标注规则）；v1 的包只在 Sources 索引中保留来源 id，并且只在
  共享事实表列出了某条计算说明时才以 `[C2]` 引用它——绝不引用事实表里没有
  的 id；
- 内部产物名称，例如 `companies.yaml`、`memo_packet`、`source_trace`、
  `claim_register`、`research_tasks`、`reviewer_prompts` 或分析文件名；
- 关于备忘录产物、登记表、来源包、保荐方说明或审阅提示词"说了什么"的来源流程
  叙述；
- 来自分析工作表、证据状态表、交割清单、预期门槛列表、投资条件列表、重新评估
  条件列表或内部问题列表的脚手架标题或标签；
- 把创始人人口统计偏好语言、论点契合度例外标签或内部使命例外用作投资理由或风险
  因素；
- 可爱或模糊的金融比喻、"无权利"式的法律简写、夸大的稀缺性措辞，或掩盖经济
  要点的简写；
- 交易法律清单倾倒，例如不解释含义就写 `MFN`、`down-round protection`、
  `named lead`、`named institutional lead`；普通的法律英语是可以的："no LP
  voting"（LP 无投票权）、"annual K-1"（年度 K-1）、"accredited investors
  only"（仅限合格投资者）；
- 被动式的交易对手能力或可获得性揣测；
- 超脱的投资建议标签式标题；用一句话直接陈述投资建议；
- 内部问题清单标签、确认事项标签、预期门槛标签或面向内部受众的后缀；
- 内部 IC、买方尽调、银行/债务、控股投资人或交易法律清单的简写。这是一份面向
  LP、可直接供高管阅读的卖方投资备忘录，不是 BSH 内部配置说明。把每一项交易
  机制、治理要点和投资建议都写成平实的叙述性文字。说清楚投资工具是什么、投资
  建议承诺什么、风险是什么。不要使用流程标签、确认事项标签、小额支票反射或处理
  式话术；
- BSH 内部的参与额度语言或内部建议指令；
- 关于备忘录/文件/分析/框架/章节的元语言，包括写作者流程措辞。

备忘录主线要求：
- core_bet：投资人要赚钱，什么必须成立；
- entry_tension：估值或投资工具已经假设了什么——当有具名、注明日期的来源给出
  市场共识（consensus_source）时，再各用一句话写出这一共识和我们的看法
  （our_view）；
- current_proof：今天已经证明了什么，点名（人、合同、日期）；
- unproven_but_modelable：还缺什么，以事实加风险的形式陈述；
- risk_sensitivity：什么会打破这个逻辑；
- action：建议的承诺出资或放弃，以句子形式，以 "Recommendation: " 开头。

主线完整地讲一次，放在开篇：正文的前两段说明公司、交易、估值 / 进入条款，以及
核心的价格/证据张力。实质性的结尾在任何来源或披露之前，重申投资建议（承诺出资
或放弃）、点名的风险，以及什么会改变数字。中间各章节只论证属于自己的那部分，
提到其他章节已论证的事实时，指回该章节（"见估值部分"），而不是再讲一遍。已钉定
的事实是例外，但有上限：共享事实表要求在多个章节出现的钉定句子或数字，在每一个
要求出现的章节里逐字写一次，而且每章最多一次——放在该章归属它的那段里。同一章
里的其他提及只指代这个事实，不再重复数字："2026 年 2 月的估值标记"、"基准
情形"、"合同与意向书的合计金额"。一份实际备忘录把同一个入场估值重复了四十九
次，把同一个合计金额重复了三十五次；读者见过一次的数字，不需要在下一段再看
一遍。投资决定章节不要把自己的正文再改写成一份要点清单。面向 LP 的备忘录中
不要包含 BSH 内部的参与额度。

早期商业化基础设施交易的正面示例（同一家虚构的 Tarnwell Robotics）：
- "Tarnwell 的叉车已经在冷冻通道里跑无人值守的班次。B 轮为真实的 IP、技术深度
  和早期商业拉力定价，此时收入曲线尚未完全显现。"
- "九个月内已签合同和意向书合计 1.4 亿美元以上，外加 900 万美元的国防物流业务。
  Carrow Freight 和 Pemberly Cold Chain 是具名客户。Ines Varga 担任董事长。"
- "管线不是已签约收入。1.4 亿美元以上的数字中相当一部分仍是意向书。"

  价格合理——投资建议取决于 12 亿美元估值下的回报。"

禁用措辞 / 改写指引：

| 避免 | 推荐 |
|---|---|
| "The investment case is not that..."（投资逻辑并不是……） | 这不是一个传统的 SaaS 案例。 |
| 超脱的投资建议框架 | Recommendation: BSH 向<标的>承诺出资…… / Recommendation: 放弃…… |
| 超脱的机会框架 | 该 SPV 是一份 800 万美元的 SAFE…… / 投资人最多可认购 $Y（仅限交易条款在档时） |
| 超脱的基准情形框架 | 点名证据。然后是风险。 |
| "we give credit to" / "our base case credits" / "the investment case rests on"（我们给予……认可 / 我们的基准情形计入 / 投资逻辑建立在……之上） | 陈述事实。去掉套路。 |
| "the investment case uses" / "valuation-support factor"（投资逻辑采用 / 估值支撑因素） | 陈述事实和风险。 |
| "Key risk centers on..."（核心风险集中在……） | 加粗的名词标签，后接一句话："SAFE risk. A SAFE is not equity."（SAFE 风险。SAFE 不是股权。） |
| 备忘录/文件/流程叙述 | 去掉框架；直接做投资陈述。 |
| 分析流程叙述 | 直接陈述结论。 |
| 为不确定性道歉 | "收入未披露。相对于已披露收入，12 亿美元偏高。" |
| 超脱的决策标签 | Investment Decision（投资决定） / Recommendation: BSH 承诺出资…… |
| 问句形式的交割清单 | 陈述交易经济条款或风险。 |
| 揣测保荐方能力 | 陈述已披露的事实和风险。 |
| 被动式可获得性语言 | 去掉对流程的猜测；陈述风险。 |
| 出资门槛清单措辞 | 陈述事实或风险。 |
| 祈使式索证措辞 | 陈述交易事实或风险。 |
| 交割清单标题 | 删除该部分；把实质内容并入投资建议、风险或交易机制。 |
| 签署流程清单措辞 | 直接陈述交易事实。 |
| 未决事项流程措辞 | 陈述已披露什么、未披露什么，以及为什么重要。 |
| 保荐方流程叙述 | 直接陈述投资事实或风险。 |
| 来源流程叙述 / "source class"（来源类别） / "model treatment"（模型处理） | 点名人、合同或出版物。把类别放进索引。 |
| 尽调门槛或后续步骤清单标签 | 并入投资建议、风险或交易机制的正文。 |
| "No voting or information rights"（无投票权或信息权）（清单倾倒） | "A SAFE is not equity and has no LP voting."（SAFE 不是股权，LP 没有投票权。） |
| "underwrite" / "underwriting"（承销 / 承保） | "rely on"（依赖） / "the case"（该论点） / 去掉这个动词 |
| "We frame it as..."（我们把它框定为……） | 直接陈述结论，不带写作者流程叙述。 |
| "Require X before underwriting"（承销前须要求 X） | X 不在已披露的条款中。 / X 仍是主要风险。 |
| 内部问题清单标签 | 删除；改用论点、风险或交易机制。 |

| 未决问询框架 | 风险因素 / 交易机制披露 |
| "Missing proof"（证据缺失） | 点名缺口，然后是风险。 |
| 投资建议标签 | Recommendation: BSH 承诺出资…… / Recommendation: 放弃…… |
